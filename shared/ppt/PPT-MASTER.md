# PPT-MASTER 슬라이드 생성 표준

> 업무와 무관한 공통 **PPT 작성·디자인·생성 표준**
> 업무별 내용(고객, 메시지, 장표 구성, 산출물)은 **업무별 PPT 구성 문서**에 별도 작성, 이 표준과 함께 전달
>
> 사용 예: "`PPT-MASTER.md` 표준에 따라 `20261020_예시기관_PPT구성.md` 내용으로 PPT 생성"

## 1. 역할

- **엔터프라이즈 IT 제안서 전문 PPT 디자이너** 겸 해당 분야 **시니어 프리세일즈 엔지니어**
- 목표: 고객 의사결정자의 빠른 이해 — "왜 해야 하는지 → 무엇을 제공하는지 → 어떻게 운영하는지 → 무엇을 결정하면 되는지"

## 2. 업무별 PPT 구성 문서 필수 항목

- 생성 전 업무별 구성 문서의 아래 항목 확인
- 누락 항목은 생성 결과의 `[자료 필요]` 목록에 기재

| 항목 | 설명 |
| --- | --- |
| 고객·청중 | 고객사, 대상(부서·직급) |
| 목적·요청 사항 | 제안 목적, 고객에게 받을 결정 |
| 사용 방식 | 발표용 / 정보 전달용(배포·열람) / 겸용 |
| 발표자 노트 | 작성 / 미작성 (기본값: 발표용·겸용은 작성, 정보 전달용은 미작성) |
| 입력 자료 | 내용 근거 문서 목록 |
| 덱 핵심 메시지 | 덱 전체 결론 한 줄 |
| 용어 | 덱 전체 통일 용어 |
| 장표 구성 | 장표별 제목, 핵심 메시지, 담을 내용, 시각화 방식 |
| 트래커 라벨 | 상단 트래커 표시용 장 이름 |
| 의미 색 지정 | 반복 구분(유형, 단계 등)별 색 |
| 로고·보안 등급 | 로고 파일 경로, 고객 로고 사용 여부, `대외비` 등 표기 |
| 산출물 | 파일명, 저장 위치, 장수 제한 |

## 3. 사실 원칙

- 입력 자료에 없는 수치·가격·고객사례·제품 기능 **임의 작성 금지**
- 자료 부재로 비는 자리: 회색 점선 박스에 `[자료 필요: 내용]` 표시
- 미정 항목(가격 등): "협의 예정" 표기
- 입력 자료 간 불일치 값: 임의 선택 금지, `[확인 필요]` 표시

## 4. 작성 원칙 (Best Practice)

### 4.1 스토리라인 — 피라미드 원칙 + SCR

- **결론 우선**: 덱 전체 핵심 메시지를 먼저 확정, 모든 장표가 이 메시지를 뒷받침하는 구조
- **SCR 흐름**: 상황(Situation) → 문제(Complication) → 해결(Resolution) → 요청(Next Step) 순서 전개
- **MECE**: 장표·블록 간 내용 중복·누락 없는 구분

### 4.2 장표 단위 원칙

- **장표 하나에 메시지 하나**: 두 가지 이상이면 압축 또는 우선순위 낮은 쪽 제외 (발표자 노트 작성 시 노트로 이동)
- **제목**: 짧은 주제형 (예: "서비스 구성", "적용 방안"), 15자 이내, 문장형 금지
- **핵심 메시지 줄**: 제목 아래 한 줄, 해당 장표의 결론을 명사형으로 요약 (예: "수집 서버 2대 기반 기관 그룹별 분리 적재 및 통합 관제")
- **수평 논리**: 표지부터 마지막 장까지 핵심 메시지 줄만 이어 읽어도 제안 전체 이해 가능
- **수직 논리**: 본문의 모든 요소가 해당 장표의 핵심 메시지를 뒷받침, 무관한 내용은 제외
- **3초 원칙**: 처음 보는 사람도 3초 안에 핵심 파악 가능
- **출처 미기재**: 장표 하단에 출처(입력 문서명) 표기 없음
- **마지막 장은 요청 사항**: 고객 결정 사항과 다음 단계로 마무리

### 4.3 문장 원칙

- **명사형 개조식** 통일 ("~ 제공", "~ 일원화", "~ 확인"), "~한다 / ~진다 / ~하자" 등 서술형 종결 금지
- 불릿 한 줄은 **약 40자 이내**
- 용어는 업무별 구성 문서의 용어 목록 기준 통일
- 숫자·단위 표기: 숫자와 단위 사이 한 칸 (`16 GB`, `4~8 Core`, `1 TB`)
- 장표당 텍스트 블록 **최대 3개**, 블록당 불릿 **최대 4개**

## 5. 작업 순서

1. 업무별 구성 문서의 **2장 필수 항목** 확인
2. **스토리라인(고스트 덱) 작성**: 장표별 제목·핵심 메시지·본문 요소(도식 종류, 내용) 표로 정리
3. 핵심 메시지 줄만 이어 읽어 **수평 논리** 점검, MECE 확인
4. **슬라이드 마스터**(그리드, 폰트 스타일, 색상 테마, 표 스타일) 우선 작성 후 장표 작성
5. 장표별 렌더링 후 **10장 완료 전 점검** 수행, 문제 수정 후 결과 제출
6. 결과와 함께 스토리라인 표, `[자료 필요]`·`[확인 필요]` 목록 제출

## 6. 디자인 표준

### 6.0 디자인 원칙 (Best Practice)

- **CRAP 4원칙**
  - **대비(Contrast)**: 중요 요소와 보조 요소의 크기·굵기·색 차이를 분명하게, 어중간한 차이(12pt vs 13pt) 금지
  - **반복(Repetition)**: 같은 의미의 요소는 덱 전체에서 같은 모양·색·크기·위치
  - **정렬(Alignment)**: 모든 요소 그리드 선 기준 정렬, 본문 글은 **왼쪽 정렬** (가운데·양쪽 정렬 금지, 표지·KPI 숫자만 예외)
  - **근접(Proximity)**: 관련 요소는 가깝게, 다른 그룹과는 더 넓은 간격
- **시각 위계 3단계**: ① 제목·핵심 메시지 → ② 핵심 도식·KPI → ③ 보조 설명 순서의 시선 유도, 가장 강한 강조는 장표당 하나
- **시선 흐름**: 왼쪽 위 → 오른쪽 아래(Z 패턴), 흐름도는 왼쪽 → 오른쪽, 계층은 위 → 아래
- **여백**: 본문 영역의 **30% 이상** 여백 확보
- **색 비율 60-30-10**: 흰 배경·회색 계열 60%, 주 색상 30%, 포인트 색상 10% 이하
- **가독성**: 글자·배경 명도 대비 **4.5:1 이상**(WCAG AA), 회색 글자는 캡션 한정
- **단순화**: 의미 없는 요소(장식선, 배경 무늬, 불필요한 테두리, 클립아트) 제외

### 6.1 도구

- **PPT-MASTER** 사용, 결과물은 **편집 가능한 네이티브 PPTX** (텍스트·도형·표가 개체로 유지)
- 아이콘·이미지는 외부 도구 검색 가능, 라이선스 문제 없는 세트 우선, 한 덱에 **아이콘 스타일 하나**(선형, 같은 선 굵기·색)
- 이미지는 고해상도(가로 1600px 이상)만 사용, 비율 변경 금지, 아이콘·도형은 가능하면 벡터(SVG/EMF)

### 6.2 테마

- **McKinsey 스타일**: 넉넉한 여백, 절제된 색, 장표마다 결론 우선
- 기술 제안 느낌의 구성도·표·프로세스 도형 중심 표현
- 장식용 사진, 그라데이션, 그림자, 3D 효과, 애니메이션·화면 전환 효과 사용 금지

### 6.3 색상

| 용도 | 색상 |
| --- | --- |
| 주 색상 (제목, 강조 도형, 트래커 현재 위치) | Navy `#0B1F3A` |
| 포인트 색상 (핵심 수치, 강조 박스) | Blue `#1F6FEB` |
| 보조 색상 (구분선, 비활성 요소) | Gray `#8A94A6` / Light Gray `#EEF1F5` |
| 본문 텍스트 | Dark Gray `#222222` |
| 배경 | White `#FFFFFF` |

- 포인트 색상은 장표당 1~2곳 한정
- 색만으로 의미 구분 금지 (흑백 인쇄·색각 이상 고려), 라벨·굵기 병행
- 의미 색은 업무별 구성 문서 지정 기준으로 덱 전체 고정
- 회사 CI 색상 확정 시 위 값 대신 CI 색상 적용

### 6.4 폰트·타이포그래피 (Pretendard 단일 사용)

| 구분 | 크기 | 굵기 | 용도 |
| --- | --- | --- | --- |
| 표지 제목 | 36pt | Bold | 표지 |
| 장표 제목 (주제형) | 22pt | Bold | 장표 상단 |
| 핵심 메시지 줄 | 14pt | SemiBold | 제목 아래 결론 한 줄 |
| 서브 제목 | 14pt | SemiBold | 본문 블록 제목 |
| 본문 | 12~14pt | Regular | 설명 |
| 표 내용 | 11~12pt | Regular | 표 셀 |
| 강조 | 본문과 같은 크기 | Bold + 포인트 색상 | 핵심 단어·수치 |
| KPI 숫자 | 28~32pt | Bold | 핵심 수치 박스 |
| 캡션·각주 | 9pt | Regular, Gray | 주석, 하단 바 |

- 위 표 외 크기 사용 금지, **본문 12pt·표 11pt 미만 축소 금지** — 넘치면 글 분량 축소
- 장표당 굵기 **최대 3가지**(Regular, SemiBold, Bold), 기울임꼴·밑줄 강조 금지
- 줄 간격 **1.3~1.5배**, 문단 간격은 줄 간격보다 넓게(약 6pt)
- 한글 자간 **-1%~-2%** 통일
- **단어 단위** 줄바꿈, 외톨이 줄(한 글자·한 단어만 넘어간 줄)은 문장 수정으로 제거
- 불릿 **2단계까지**, 불릿 기호·들여쓰기 폭 덱 전체 통일
- 텍스트 상자 자동 맞춤(글자 자동 축소) 해제
- 폰트 **파일 임베딩**, 임베딩 불가 시 대체 폰트는 맑은 고딕

### 6.5 레이아웃 (모든 장표 공통)

- 슬라이드 비율: **16:9**
- 여백: 좌우 0.6인치, 상단 0.5인치, 하단 0.4인치
- 모든 장표 동일 위치 구조
  1. **상단 트래커**: 업무별 구성 문서의 트래커 라벨, 현재 장만 주 색상
  2. **장표 제목**: 짧은 주제형 (1줄)
  3. **핵심 메시지 줄**: 결론 한 줄 (명사형)
  4. **본문 영역**: 12열 그리드 (1단 / 2단 6:6 / 2단 4:8 / 3단 4:4:4 중 선택), 열 간격 0.25인치 고정
  5. **하단 바**: 오른쪽 `{회사명}` 표기와 페이지 번호 (출처 미기재, 보안 등급은 구성 문서에서 지정한 경우에만 가운데 표기)
- 위치는 **슬라이드 마스터**로 고정, 장표별 개별 이동 금지
- 간격은 **8pt 배수**(8 / 16 / 24 / 32pt) 한정
- 같은 위계 요소(카드, 박스, 아이콘)는 **동일 크기**
- 장표당 주요 시각 요소(도식·표·카드 묶음) **최대 2개**

### 6.6 표·도형 스타일

- **표**: 머리행 주 색상 배경 + 흰 글자 Bold, 본문 행 흰 배경, 행 구분선만 Light Gray 0.75pt (세로선 없음), 숫자 오른쪽·글 왼쪽 정렬, 셀 여백 상하 4pt·좌우 6pt, 강조 행·열 하나만 Light Gray 배경
- **도형**: 직각 모서리(또는 아주 작은 둥근 모서리로 통일), 테두리 1pt, 채움은 Light Gray 또는 흰색
- **화살표·연결선**: 한 가지 스타일(실선, 1.5pt, 끝 화살표), 직각 꺾은선, 선 교차 없는 배치
- **강조 박스**: 왼쪽 포인트 색상 세로 띠(4pt) + Light Gray 박스
- **아이콘**: 24pt 또는 32pt 중 하나로 통일, 주 색상 단색, 블록 제목 옆 보조용, 장표당 6개 이하

### 6.7 구성도(아키텍처 다이어그램)

- 도형과 화살표로 직접 작성 (이미지 붙여넣기 금지)
- **영역(Zone) 구분**: 논리·물리 영역을 점선 또는 Light Gray 박스로 묶음
- 같은 계층 요소는 같은 크기·같은 간격으로 나란히 배치
- 흐름 방향 하나로 통일, 핵심 데이터 흐름 선만 포인트 색 강조
- 구성 요소마다 짧은 라벨(제품명·역할), 범례는 오른쪽 아래 한 번만

### 6.8 데이터·수치 표현

- 비교는 표 또는 나란한 카드, 핵심 수치는 KPI 박스
- KPI 박스는 **큰 숫자 + 단위 + 한 줄 설명** 구조 통일
- 차트 하나에 메시지 하나, 강조 값만 포인트 색, 나머지는 Gray
- 범례 대신 값 옆 직접 라벨, 막대 차트 축 0 시작, 원형·3D 차트·배경 격자 사용 금지

### 6.9 로고·표지

- 표지 구성: 제목, 부제(고객명), 제안사 로고, 날짜, 문서 버전, 보안 등급
- 로고는 원본 비율 유지, 주변에 로고 높이 절반 이상 여백
- 고객 로고는 업무별 구성 문서에서 사용 승인 확인 시에만 사용

## 7. 발표자 노트

- 업무별 구성 문서에서 **"작성"** 지정 시에만 작성, "미작성"이면 노트 칸 공란
- 작성 시 장표마다 2~4줄: 장표 결론 → 근거 → 다음 장 연결 문장, 장표에서 뺀 상세 설명·예상 질문과 답변 포인트 포함
- **정보 전달용(노트 미작성)**: 설명자 없이 읽히는 문서, 장표만으로 이해 가능한 구성
  - 제목·핵심 메시지 줄·블록 제목만으로 흐름 연결
  - 약어·제품명은 첫 등장 시 짧은 풀이 병기
  - 도식에는 설명 없이도 읽히는 충분한 라벨

## 8. 분량 조절

- 내용 초과 시 장표 추가 대신 **압축**, 상세는 발표자 노트(작성 시) 또는 각주·별첨 문서로 이동
- 장수 제한은 업무별 구성 문서 기준

## 9. 산출물 기본값
