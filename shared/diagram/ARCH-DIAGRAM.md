# ARCH-DIAGRAM 논리 구성도 표준 v1.0

> **디자인은 이 표준이, 내용은 YAML이** 정함 — 위치·크기·색·선·글자는 고정, 계층 이름·노드·칩·연결선만 업무마다 받음
> 생성: `python3 scripts/arch-diagram.py {내용.yaml} --fragment` (장표용) / `--svg {파일} [--icons-dir …]` (단독·미리보기)
> 내용 양식: `arch-diagram-template.yaml` · PPT 표준 `PPT-MASTER.md` 6.7(구성도)이 이 문서를 따름

## 1. 원칙

1. **노드 기준**: 단위는 서버(노드) — 플랫폼 내부 리소스(Service·ConfigMap·Secret·Pod·CRD, 정책 엔진, 자동 확장 기능 등)는 그리지 않음
2. **개별 표시**: 노드는 묶지 않고 한 대씩 (`Master 1/2/3`) — `× N` 배지 금지, 수평 확장은 마지막 `N` 점선 타일
3. **공백 최소화**: 내용 영역(본문 ⑤)을 끝까지 채움 — 빈 칸은 연결선 통로로만
4. **아이콘·색·모양이 먼저, 글은 짧게**: 타일 = 아이콘 사각 + 분류 라벨 + 이름 + 사양·설명
5. **서비스는 실행 노드 안 칩으로**: 별도 띠·박스로 그리면 노드로 오해함 — 노드에 나눠 한 번씩만, 실행 노드 근거가 없으면 `[확인 필요]`

## 2. 화면 구조 (왼쪽 → 오른쪽)

```text
 사용자 ──────────────   {주 영역 제목} ─────────────── {기술 캡션}   {오른쪽 계층} ────
 [행위자] [입구·관리]   ┌ ─ ─ ─ ─ ─ ─ ─ 점선 박스 ─ ─ ─ ─ ─ ─ ─ ─ ┐   [고객 인프라 등]
                        │ ■ 네트워크 구간 A  │ ■ 네트워크 구간 B       │
                        │ [열 1 노드]        │ [열 2 노드] [열 3 노드] │
                        └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
                                                              범례 ── ── ── □ □
```

| 영역 | 규격 (본문 영역 1164.8 × 463 px 기준, 스크립트가 계산) |
| --- | --- |
| 계층 제목 | 모든 계층 같은 형식 — 박스 밖 위쪽 11 px Bold Caption Gray + 밑줄 1 px `#C5CCD6`, 주 영역 오른쪽 끝에 기술 캡션(11 px Regular) |
| 왼쪽 계층 (사용자) | 너비 284 px — 행위자 열(80 px) + 입구·관리 열(144 px: LB, Bastion 등). 별도 "경계" 제목 없음 |
| 주 영역 | **유일한 박스** — 점선 `#7F97B8` 1 pt (6,4), 모서리 8 px, 바탕 `#FAFBFD` |
| 네트워크 구간 | 주 영역 안 테두리 없는 색 구역 + 왼쪽 위 8 px 색 사각·라벨 (5장) |
| 주 영역 열·행 | 역할별 열(상대 폭 지정, 간격 16 px), 행 수 지정(간격 16 px) — 같은 번호끼리 같은 행 (`Ingress 1 → Worker 1 ← Master 1`) |
| 오른쪽 계층 (선택) | 너비 144 px — 고객 인프라·외부 연계 등, 타일 120 px |
| 범례 | 내용 영역 오른쪽 아래 한 줄 — 실제로 쓴 연결선 종류 + 칩 종류 |

## 4. 타일·칩

| 요소 | 규격 |
| --- | --- |
| 기본 타일 | 흰 바탕, 테두리 `#D5DBE3` 1 pt, 모서리 6 px — 아이콘 사각 28 px(분류 색, 흰 아이콘 20 px) + 분류 라벨 11 px Bold(분류 색) + 이름 13.33 px Bold Navy + 사양·설명 11 px Caption Gray, 각 한 줄 |
| 행위자 | 80 × 80 px, 아이콘 사각 + 이름 |
| 칩을 가진 노드 | Navy 테두리, 왼쪽 정보 120 px + 세로 구분선 + 칩 2열 — 맨 위 한 줄은 **모든 노드 공통 칩**(업무·에이전트, 옅은 색 바탕), 그 아래 `플랫폼 서비스` 소제목 + **서비스 칩**(흰 바탕 + 회색 테두리 + 분류 색 아이콘) |
| 보조 목록 | 한 서버 안 여러 도구는 회색 칩 격자 (예: 관리 서버의 Registry·Git·CI) |
| 확장 노드 | 점선 Navy 테두리 + 회색 아이콘 사각, 분류 라벨 `… · 확장`, 공통 칩만 + 안내 문구 |
| 고객 준비 | 점선 회색 테두리 — 반드시 준비할 항목은 오른쪽 위 테두리에 걸친 Navy `필수` 배지 (32 × 18 px) |
| 선택 구성 | 분류 라벨에 `· 선택` |
| 글자 크기 | 이름 13.33 px(10 pt), 그 밖 11 px — PPT-MASTER 6.4 최소 크기의 예외(도식 라벨), 넘치면 글자 축소가 아니라 문구 압축 |

## 6. 연결선

| type | 모양 | 용도 |
| --- | --- | --- |
| service | Blue `#1F6FEB` 실선 2 pt | 사용자 요청 경로 |
| control | Gray `#8A94A6` 실선 1.5 pt | 관리 접속, 제어 노드 → 업무 노드 |
| data | Gray `#5B6577` 실선 2 pt | 스토리지·DB 읽기·쓰기 |
| deploy | Indigo `#3B4BB5` 실선 2 pt | 이미지 배포, CI/CD |
| monitor | Green `#2F855A` 점선 1.5 pt | 수집·모니터링 (칩으로 표현되면 생략) |

- 직각 꺾은선, 열 사이·행 사이 통로로만 — 노드 관통은 오류
- **분기** `to: [a, b]`: 통로에서 직각 분기 / **합류** `from: [a, b]`: 통로에서 합류 후 한 선
- 같은 입구를 쓰는 접속(사용자·운영자)은 입구 앞에서 합류 — 입구를 따로 그리지 않음
- 화살촉 중간 크기 (`markerWidth 3` → PPTX `med`), 3.5 이상은 `lg`로 커짐
- 선 라벨(`label`)은 짧게, 선 위 빈 칸에

## 7. 내용 YAML (요약 — 전체 양식은 `arch-diagram-template.yaml`)

| 키 | 내용 |
| --- | --- |
| `services` | 칩 이름 → `icon`·`category`·`tint`(application / ops — 공통 칩 바탕색) |
| `left` | `label`, `actors`(행위자: `row`), `nodes`(입구·관리: `row` 또는 `rows: [a, b]`, `chips`) |
| `main` | `label`, `caption`, `rows`, `columns`(`id`·`width`), `networks`(`kind`·`label`·`cols`), `nodes`(`col`·`row`·`label`·`category`·`caption`·`spec`·`sub`·`common`·`services`·`note`·`dashed`) |
| `right` | `label`, `nodes`(`row`·`customer`·`required`) |
| `edges` | `from`·`to`(목록 = 합류·분기)·`type`·`label` |

- 내용은 제품 문서의 근거 있는 값만 — `[추정]`·`[확인 필요]`·`[내부]` 항목은 넣지 않음
- 좌표·크기·색은 쓰지 않음 (디자인은 스크립트가 고정)
