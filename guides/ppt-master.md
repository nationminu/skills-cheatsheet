# ppt-master 스킬 가이드

> 편집 가능한 **네이티브 PPTX**(텍스트·도형·표가 개체로 유지되는 파일)로 제안서·보고서 덱을 만드는 스킬
> 원본: [hugohe3/ppt-master](https://github.com/hugohe3/ppt-master) — claude.ai용 스킬은 실행 시 원본 저장소를 받아 워크플로우를 로드하는 경량 래퍼

> 💡 표준을 매번 첨부하지 않으려면 오버레이 스킬(`om-ppt-proposal` 등) 사용 — [README 치트시트](../README.md) 참고

## 1. 한눈에 보기

| 구분 | 내용 |
| --- | --- |
| 쓰는 경우 | 고객 제안서, 기술 보고서, 내부 보고 덱 — 받은 뒤 **직접 수정**해야 하는 PPT |
| 안 쓰는 경우 | 한두 장짜리 간단 정리(대화로 충분), 이미지 한 장으로 끝나는 구성도(drawio 스킬) |
| 입력 | ① 공통 표준 `shared/ppt/PPT-MASTER_생성표준.md` ② 업무별 구성 문서 ③ 근거 자료(제안요청서, 기술 문서 등) |
| 출력 | `.pptx` 파일 + 스토리라인 표 + `[자료 필요]`·`[확인 필요]` 목록 |
| 소요 | 10장 기준 수십 분 (렌더링·점검 반복 포함) |

## 2. 동작 방식

```text
요청 ─▶ setup.sh (원본 저장소 내려받기)
     ─▶ 원본 SKILL.md 로드 (routing → 선택된 workflow)
     ─▶ 스토리라인(고스트 덱) 작성
     ─▶ 슬라이드 마스터 → 장표 SVG 작성 → 렌더링 점검
     ─▶ svg_to_pptx 변환 ─▶ .pptx 전달
```

- 실행 환경에서 **GitHub 접근이 필요**함 — 네트워크가 막혀 설치가 실패하면 Claude가 내장 `pptx` 스킬로 진행할지 물어봄
- 작업 폴더는 세션이 끝나면 사라짐 → 결과 파일은 반드시 대화창에서 다운로드
- "빠르게 / 간단히 / 확인 없이"를 요청에 넣으면 Quick Generate 모드(중간 확인 생략)로 동작

## 3. 문서 2단 구조 (핵심)

| 문서 | 역할 | 바뀌는 주기 | 위치 |
| --- | --- | --- | --- |
| **생성 표준** | 역할, 사실 원칙, 작성 원칙, 디자인(색·폰트·레이아웃), 점검표 | 거의 고정 (팀 합의로 개정) | [`shared/ppt/PPT-MASTER_생성표준.md`](../shared/ppt/PPT-MASTER_생성표준.md) |
| **업무별 구성 문서** | 고객·청중, 목적, 핵심 메시지, 장표 구성, 산출물 | 업무마다 새로 작성 | [`shared/ppt/구성문서_양식.md`](../shared/ppt/구성문서_양식.md) 복사 |

**왜 나누는가**
- 디자인·문장 규칙을 매번 다시 쓰지 않음 → 팀 전체 덱의 일관성 유지
- 업무 문서는 "무엇을 말할지"에만 집중 → 작성 시간 단축
- 표준 개정 시 한 곳만 수정

## 4. 사용 절차

### Step 1. 업무별 구성 문서 작성

1. `shared/ppt/구성문서_양식.md` 복사 → 파일명 변경 (예: `20261020_사회보장정보원_PPT구성.md`)
2. 표준 2장의 **필수 항목 12개** 채우기 — 비워 둔 항목은 결과의 `[자료 필요]` 목록으로 돌아옴
3. 가장 공들일 곳: **덱 핵심 메시지 한 줄**과 **장표별 핵심 메시지 줄** — 이것만 이어 읽어도 제안이 이해되면 성공

### Step 2. Claude에 요청

- 첨부: 생성 표준 + 업무별 구성 문서 + 근거 자료
- 요청 문구 (기본형):

```text
ppt-master 스킬로, PPT-MASTER_생성표준.md 표준에 따라
20261020_사회보장정보원_PPT구성.md 내용으로 PPT 생성해줘.
```

- 상황별 문구는 [`ppt-master-prompts.md`](ppt-master-prompts.md) 참고

### Step 3. 스토리라인 먼저 확인 (권장)

- 장표를 만들기 전에 **스토리라인 표만 먼저** 받아 검토하면 재작업이 크게 줄어듦
- 확인 포인트: 핵심 메시지 줄의 흐름(SCR), 장표 간 중복, 마지막 장의 요청 사항

### Step 4. 결과 점검 → 수정 요청

- 표준 **10장 점검표**로 확인 (스토리 / 사실 / 디자인 / 형식)
- 수정은 장표 번호를 지정해 짧게 요청 (예: "5장 구성도에서 DB 영역을 오른쪽으로, 연결선 교차 제거")
- `[자료 필요]` 항목은 자료를 추가 첨부해 재요청하거나 PPT에서 직접 채움

### Step 5. 마무리

- PowerPoint에서 열어 폰트·줄바꿈 최종 확인
- 파일명 규칙: `YYYYMMDD_고객명_제안명_v1.0.pptx`
- 버전 올릴 때는 구성 문서도 함께 갱신해 두면 다음 버전 생성이 쉬움

## 5. 잘 나오게 하는 요령

| 요령 | 이유 |
| --- | --- |
| 장표 구성에 **시각화 방식**까지 지정 (표 / 구성도 / 3단 카드 / KPI 박스) | 지정하지 않으면 불릿 위주 장표가 나오기 쉬움 |
| 근거 자료는 **필요한 부분만** 첨부 | 자료가 많을수록 핵심 메시지가 흐려짐 |
| 용어 목록을 구성 문서에 명시 | "수집기 / 에이전트 / 컬렉터" 같은 혼용 방지 |
| 장수 제한을 명시 | 제한이 없으면 내용을 장표로 쪼개 분량이 늘어남 |
| 한 번에 전부 고치려 하지 말고 **장 단위**로 수정 | 수정 범위가 좁을수록 다른 장표가 망가지지 않음 |

## 6. 알려진 제약·문제 해결

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| 설치 단계에서 실패 | 실행 환경의 GitHub 접근 차단 | 내장 `pptx` 스킬로 진행하거나 잠시 후 재시도 |
| Pretendard가 아닌 폰트로 보임 | 원본 워크플로우의 한국어 기본 폰트는 맑은 고딕, 실행 환경에 Pretendard 미설치 | 요청에 "폰트 Pretendard 지정" 명시, 받은 뒤 PowerPoint에서 폰트 일괄 바꾸기·임베딩 |
| 글자가 도형 밖으로 넘침 | 표준상 글자 자동 축소 금지 → 분량 초과 | "해당 장 문장 압축" 요청 (폰트 축소 요청 금지) |
| 결과 파일이 사라짐 | 세션 작업 폴더는 임시 공간 | 대화창 파일 카드에서 즉시 다운로드 |
| 숫자·사례가 근거 없이 들어감 | 근거 자료 누락 또는 구성 문서에 수치 기재 | 표준 3장(사실 원칙) 재확인 요청, 해당 값 `[확인 필요]` 처리 |
